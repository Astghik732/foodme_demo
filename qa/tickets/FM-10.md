## Description

Support has been fielding a steady stream of customers asking to cancel an
order right after placing it — usually within a minute or two, typically
because they picked the wrong chef, mistyped their address, or ordered by
accident. Right now there is no way for a customer to cancel; they have to
call the chef directly and hope the order hasn't already been accepted.

This has come up often enough that it needs a real flow, not a workaround.
None of the existing specs (`docs/requirements/`) mention order cancellation
by the customer at all — the order status machine documented for the admin
side only covers `NEW → ACCEPTED → DELIVERED` and `REJECTED` (chef-initiated).

## Steps to reproduce

N/A — this is a requirement gap, not a reproducible defect. To see the gap
directly:

1. Place an order as a customer.
2. Try to find any way, on the tracking page or anywhere else in the
   storefront, to cancel it.

## Expected vs actual

**Expected:** it's reasonable for a customer to assume they can cancel an
order shortly after placing it, before a chef has started preparing it.

**Actual:** no cancellation entry point exists anywhere in the customer-facing
flow. The only status transitions defined anywhere are chef/admin-initiated
(`NEW → ACCEPTED → DELIVERED`, or `REJECTED`).

## Open questions for grooming

- Is cancellation only allowed while the order is `NEW` (not yet `ACCEPTED`),
  or should there be a grace period even after acceptance?
- Does the customer need to prove ownership of the order to cancel it (see
  the tracking-page access question raised in FM-4), or is the order number
  alone sufficient?
- Does the chef get notified when a customer cancels, and is that different
  from a chef-initiated `REJECTED`?
- Is there a cutoff after which cancellation is no longer offered (e.g. once
  `ACCEPTED`, or after N minutes)?
- Should a cancelled order use a new terminal status, or reuse `REJECTED`?

## Environment

Applies to the storefront tracking page and would require new backend
support (`docs/api-contract.md` has no cancellation endpoint today).
